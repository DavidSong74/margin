## 2024-05-24 - [PostgreSQL RPC Authorization Bypass via SECURITY DEFINER]
**Vulnerability:** A Supabase RPC function (`save_correction`) was created with `security definer`. This meant the function executed with the permissions of the user that created it (usually the superuser/postgres admin), bypassing Row Level Security (RLS) entirely. A malicious authenticated user could therefore supply any `p_user_id` and bypass RLS to modify another user's glossary or correct pages belonging to others.
**Learning:** Supabase and PostgreSQL functions default to `security invoker` (which enforces RLS on the tables based on the calling user), but developers sometimes unnecessarily explicitly declare `security definer`. If `security definer` is used without strict inside-function checks (`auth.uid() = p_user_id`), it leads to complete authz bypass on the tables affected by the function.
**Prevention:** Always default to `security invoker` for PostgreSQL functions that interact with RLS-protected tables unless there is a specific, explicitly justified reason to bypass RLS, in which case the function MUST contain its own rigorous access control checks.
