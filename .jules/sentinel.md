## 2024-05-15 - [Email Masking Leak & Search Path Hijacking]
**Vulnerability:** PII Leak in email masking logic for short emails due to PostgreSQL `regexp_replace` behavior, and insecure `search_path` in `SECURITY DEFINER` functions.
**Learning:** In PostgreSQL, `regexp_replace` replaces only the matched substring and leaves the rest of the string intact. When concatenating heavily obfuscated/masked strings, this can inadvertently duplicate remnants of the original unreplaced string (e.g., domain names in emails) if the regex fails to match. Additionally, `SECURITY DEFINER` functions must explicitly bind their execution context (`SET search_path = `) and schema-qualify all built-ins (e.g. `pg_catalog.lower`) to prevent search path hijacking (privilege escalation).
**Prevention:** Use simple string manipulation functions (e.g., `left` and `split_part`) instead of complex regexes for masking short strings. Always set `search_path = ` in `SECURITY DEFINER` functions and prefix built-ins with `pg_catalog.`.
