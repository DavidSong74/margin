## 2024-05-14 - [Critical] Search Path Hijacking in Supabase RPC Functions
**Vulnerability:** Found `SECURITY DEFINER` Postgres functions using insecure `search_path` configurations (e.g. `SET search_path = public`). This leaves the functions vulnerable to search path hijacking, allowing an attacker to intercept unqualified object references (e.g. function calls or operators) and execute malicious code with the privileges of the function owner (privilege escalation).
**Learning:** Even if functions set `search_path = public`, this can still be vulnerable if a user has permission to create objects in the `public` schema. When creating `SECURITY DEFINER` functions, the execution context must be strictly sanitized.
**Prevention:** Always use `SET search_path = ''` on `SECURITY DEFINER` functions to clear the search path entirely, and ensure all database object references (schemas, tables, functions) are explicitly schema-qualified (e.g. `public.users` instead of `users`).
